# 数値計算の堅牢化方針（層 3: 横断概念）

数値計算では、ゼロ除算・特異点・発散・NaN 伝播が起こりやすい。
これらの扱いをレイヤーごとにバラつかせると、同じ現象が場所ごとに違う閾値・
違う比較演算子で握りつぶされ、原因追跡が困難になる。
そこで全層で**統一した判定規則**を定める。

## NaN と inf の意味を分ける

- **NaN**: 「その要素は未定義／評価対象外」を表すためにのみ使う。
  異常・バグ検知の手段として NaN を書き込まない（必要なら別フラグやログで表す）。
- **inf**: 値としては**常に禁止**。`np.isinf` で検出したら例外を送出する。
- **バリデーション**: 範囲チェックは `np.isfinite` で有限値だけにマスクしてから行い、NaN はスキップする。
- **集約・評価**: 残差・平均・最小二乗・ノルムなどは、先に `mask = np.isfinite(array)` で
  評価対象を選んでから適用する。NaN を含む配列へ `np.mean` / `np.sum` / `np.linalg.norm` を直接かけない。

## クランプ（ガード）の比較演算子を統一する

ゼロ除算・特異点回避のための極小ガード `eps` と極大ガード `max_mag` は、
**比較演算子を全層で一致**させる。ここがレイヤーごとに `<` と `<=` で揺れると不整合の温床になる。

- **極小ガード**: `abs(x) <= eps` をクランプ対象にする（`eps` ちょうども近接ゼロ扱い、`<` ではなく `<=`）。
- **極大ガード**: `~np.isfinite(x) | (abs(x) >= max_mag)` をクランプ対象にする（`>` ではなく `>=`）。
  - `max_mag` は原則、対象スケールに応じた設定値として注入する。
- **クランプ後の置換値**: 変換式・物理式・評価指標の整合を保つ値に置換する。

> 例（このプロジェクトでの適用）
>
> アドミタンス→インピーダンス変換、Ohm／Kirchhoff、slip の分母、角周波数 `omega` の
> 分母で極小ガードを使う。`max_mag` は原則 `1 / eps` とし、$Z = 1/Y$ のような物理的整合を
> 保つため、極小 → `max_mag`、極大 → `eps` のように対応させる。

### 例外（意図的に別契約とするもの）

許容誤差の判定（収束判定など）は、数値ガードの `eps` と混同しない。
`tolerance` / `threshold` という別名を使い、`<` か `<=` かを関数の docstring（契約）に明記する。

## 役割分担

- **値オブジェクト／DTO**: 値・単位・状態の保持と単位変換のみ。クランプや数値安定化イベントの記録は持たない。
- **計算ロジック層**: クランプ判定と、発火を**数値安定化イベント**として集計し、
  出力 DTO／レポート等へ記録する責務を持つ。

## 単位への注意

`eps` は対象量のスケールや単位に依存する。異なる単位・次元の値に同じ `eps` を流用する場合は、
演算子統一とは別に**単位分離が必要か**を個別に検討する（暫定流用なら `# NOTE:` で理由を残す）。

> 例（このプロジェクトでの適用）
>
> Ω 等の物理量しきい値を、slip のような無次元量へ流用している箇所は、
> 将来的に単位ごとのしきい値へ分ける必要があるかを個別に確認する。
