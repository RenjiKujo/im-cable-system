# Outputアルゴリズム設計前提

## 概要

Output アルゴリズムは、物理計算結果を可視化・比較しやすい形へ整え、ファイルへ
出力する責務を持つ。ここでは、軸の扱い方、artifact の設計、build と export の
分離方針を記載する。

## 図表専用 DTO を作らない

図・表は `OutputDto` の生量（`array_layout` / `result` / `im_pc_catalogs`）から
都度派生計算する。中間の図表専用 DTO は置かない。

図表専用 DTO を挟むと、同じ派生量（出力比・電流比・力率など）の定義が DTO 側と
Builder 側に二重化し、片方だけ変更されて食い違う。`OutputDto` を単一の入力源に
固定することで、派生計算の定義を Builder に一本化できる。

代わりに、派生計算のうち複数 Builder で共有するもの（系列抽出・比率計算・単位
変換など）は、形状ごとの共有モジュール（`supply_grid/series.py`、`ratios.py` 等）
へ切り出す。

## 参照軸の扱い

横軸と表示形式は `OutputDto.array_layout.reference_axes` で決まる。

- `[SLIP, INPUT_LINE_VOLTAGE, FREQUENCY]`（supply_grid 形状）: 供給条件 (V, f) の
  組み合わせごとに条件を固定し、slip 方向の 1 次元スライスを取り出す。
- `[SLIP]`（operating_points 形状）: 運転点のリスト番号を横軸とする時系列表示。

slip は 0〜1 の範囲を取りうるが、入力データが全範囲を覆う必要はない。補間や
外挿が必要になった場合は、Builder の内部に直接埋め込まず、独立コンポーネント
として切り出す。

## slip 軸と出力比軸

supply_grid 形状では両方を生成する。

- **slip 軸**: 回路モデルの生の計算結果を確認するのに向く。力率・線電流の
  大きさ・出力・効率・トルクを並べる。
- **出力比軸**: カタログや運用上の性能評価と比較しやすい。定格出力に対する比率を
  横軸とし、電流比・回転数・力率・効率を並べる。

同じ出力比を複数の slip が満たす場合は、小スリップ側を代表点として扱う。高度な
選択条件が必要になった場合は、代表点選択を Strategy として切り出す。

## カタログ比較

カタログ性能カーブは、シミュレーション結果と同じ軸へ変換して重ね描きする。これに
より、パラメータ推定やモデル妥当性の確認で、どの領域にズレが残っているかを視覚的に
確認できる。

比較では、参照面と単位を揃えることを優先する。カタログ値そのものが自己無矛盾で
ない場合があるため、完全一致を前提にした評価は避ける（構造的な理由は
[`../execute/estimate_params_curve_fitting_consistency.md`](../execute/estimate_params_curve_fitting_consistency.md) を参照）。

## build と export の分離

build ステップ（`make_figure` / `make_table` / `make_report`）は artifact を
組み立てるところまでを責務とし、**保存先の決定・ファイル書き出しは行わない**。
パス解決と直列化は export ステップ（`export_figure` / `export_table` /
`export_report`）に寄せる。

この分離により、出力先ディレクトリやファイル名規則を変えても Builder を触らずに
済む。逆に、図の内容や表の列を変えても Exporter は無改修で済む。

artifact の型は描画・出力ライブラリの型をそのまま使う（`Figure` / `DataFrame`）。
ライブラリ非依存の中間表現は挟まない。差し替えの必要が生じた時点で検討する。

## 出力を config で個別にゲートする

図の保存・図の表示・表の保存・レポートの保存は、それぞれ独立した config キーで
判定する。まとめて 1 つのフラグにしない。

保存はしたいが画面表示は不要（CI・バッチ実行）、表示だけ見たい（対話的な検討）
といった要求が実際に混在するためである。図については「保存 or 表示のどちらかが
有効なときだけ build する」ことで、両方無効なら描画コスト自体を回避する。

同一の `Figure` オブジェクトを保存と表示の両方へ渡し、処理後は `finally` で必ず
`plt.close` する。保存のみの経路でも閉じないと matplotlib がメモリを保持し続ける。

## モード別オーケストレーターを共通化しない

3 つのモード別オーケストレーターは `run` の骨格とゲート判定が似ているが、意図的に
共通化していない。

出力はモードごとに図の種類数（1 種 / 2 種）、表の形状、レポートの有無が異なり、
共通化すると分岐フラグが増えて可読性が落ちる。モードが増えたときも、既存モードを
壊さずにオーケストレーターを 1 つ足すだけで済む形を優先する。
