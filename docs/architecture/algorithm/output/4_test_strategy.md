# Outputアルゴリズムテスト方針

## 概要

Output アルゴリズムのテストでは、`ItmDto` から `OutputDto` への変換と、各 artifact
（図・表・レポート）が設計どおりに組み立てられることを検証する。描画結果の見た目
そのものではなく、データ構造・軸・系列・列・保存経路を確認する。個々のテストケースの
詳細はテストコードを正とし、この文書ではテストの粒度と責務分担を示す。

## テストの粒度

ステップごとに対応する粒度で分ける。

- **convert テスト**: `ItmDto` から `OutputDto` が構築され、入力原値と結果の生量が
  欠落なく移されること。
- **make_figure テスト**: `OutputDto` から `Figure` が構築されること。x 軸と各 y 系列の
  長さ・単位・対応関係が崩れないこと。派生計算（系列抽出・比率・単位変換）は
  共有モジュール単位でも検証する。
- **make_table テスト**: `DataFrame` の列順・行順・派生量が仕様どおりであること。
  `array_layout` に無い軸の列が省かれること。
- **make_report テスト**: `ReportDto` の各フィールド（フィット要約・曲線行・
  catalog マッピング）が正しく組み立てられること。フィット要約が無い場合に `None`
  を返すこと。
- **export テスト**: 保存先パス解決と直列化結果（CSV の列・YAML の構造）が
  仕様どおりであること。
- **Orchestrator テスト**: `run` が config のゲートに従って各ステップを呼び分け、
  `OutputDto` を返すこと。

## 形状別の観点

**supply_grid（ForwardByCartesianGrid / EstimateParams）**

- slip 軸図で、供給条件 (f, V) ごとのサブプロットが参照軸の組み合わせと対応すること。
- 出力比軸図で、定格値を使った出力比・電流比の計算が一貫していること。
- カタログ性能カーブがある場合、同じ (f, V) 条件へ重ね描きされること。
- カタログが無い場合でも、シミュレーション由来の図表生成が継続できること。
- 表が slip × (V, f) の直積を long 形式へ展開し、カタログ列が対応行へ付くこと。

**operating_points（ForwardByOperatingPoints）**

- 運転点を横軸に、複数の縦軸へ量が振り分けられること。
- 表の列順が図の軸順と対応すること。

## config ゲートの検証

出力の有効・無効は独立したキーで制御されるため、組み合わせを検証する。

- 図の保存のみ有効／表示のみ有効／両方有効／両方無効で、build と保存・表示の
  呼び出し回数が期待どおりであること。
- 両方無効なら図を build しないこと。
- 表・レポートのゲートが図のゲートと independent に効くこと。

## EstimateParams レポート

- フィット要約 CSV・推定モデル catalog YAML・数値安定化 CSV の 3 artifact が、
  同じ `ReportDto` から生成されること。
- 数値安定化イベントが catalog YAML に混入しないこと（専用 CSV へ分離）。
- `ReportDto` が `None` のとき、どの artifact も保存されないこと。

## 統合

Processor 層を含む統合テストでは、`ItmDtos` から `OutputDtos` への件数・順序と、
期待するファイルが出力先に生成されることを smoke として確認する。
